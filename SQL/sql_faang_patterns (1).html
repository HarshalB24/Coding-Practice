PATTERN 01
🪟 Window Functions
ROW_NUMBER · RANK · DENSE_RANK · LAG · LEAD · NTILE · FIRST_VALUE
Window functions perform calculations across a set of rows related to the current row WITHOUT collapsing them (unlike GROUP BY). They're the most tested SQL concept at FAANG. Know PARTITION BY, ORDER BY inside OVER() clause, and the difference between RANK vs DENSE_RANK vs ROW_NUMBER.
Medium
MetaGoogle
Find the second highest salary in each department ▼
Given an Employee table with columns emp_id, name, department, salary — find the employee(s) with the 2nd highest salary in each department. Handle ties correctly.
📋 Table: Employee
ColumnTypeNotes
emp_idINTPrimary Key
nameVARCHAR
departmentVARCHAR
salaryDECIMAL
✅ Solution
-- Using DENSE_RANK to handle ties correctly WITH ranked AS ( SELECT emp_id, name, department, salary, DENSE_RANK() OVER ( PARTITION BY department ORDER BY salary DESC ) AS rnk FROM Employee ) SELECT emp_id, name, department, salary FROM ranked WHERE rnk = 2;
Key insight: Use DENSE_RANK() not ROW_NUMBER() — if two people share the highest salary, ROW_NUMBER would skip the actual 2nd distinct salary. DENSE_RANK gives consecutive ranks without gaps.

ROW_NUMBER vs RANK vs DENSE_RANK:
• ROW_NUMBER: 1,2,3,4 (always unique)
• RANK: 1,1,3,4 (gaps after ties)
• DENSE_RANK: 1,1,2,3 (no gaps — preferred for "Nth highest")
Hard
AmazonUber
Month-over-month revenue growth percentage ▼
Given an orders table with order_date and revenue, calculate the month-over-month revenue growth % for each month.
📋 Table: orders
ColumnType
order_idINT
order_dateDATE
revenueDECIMAL
✅ Solution
WITH monthly AS ( SELECT DATE_FORMAT(order_date, '%Y-%m') AS month, SUM(revenue) AS total_revenue FROM orders GROUP BY 1 ) SELECT month, total_revenue, LAG(total_revenue) OVER (ORDER BY month) AS prev_revenue, ROUND( (total_revenue - LAG(total_revenue) OVER (ORDER BY month)) * 100.0 / NULLIF(LAG(total_revenue) OVER (ORDER BY month), 0), 2 ) AS growth_pct FROM monthly ORDER BY month;
Key insight: LAG(col) accesses the previous row's value. LEAD(col) accesses the next row. Always wrap divisor in NULLIF(..., 0) to avoid division-by-zero errors.
Medium
GoogleLinkedIn
First and last purchase date per customer ▼
From an orders table, find the first and last order date for each customer, along with the order amounts on those dates.
✅ Solution
SELECT DISTINCT customer_id, FIRST_VALUE(order_date) OVER ( PARTITION BY customer_id ORDER BY order_date ASC ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS first_order_date, LAST_VALUE(order_date) OVER ( PARTITION BY customer_id ORDER BY order_date ASC ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING ) AS last_order_date FROM orders;
Critical gotcha: LAST_VALUE requires ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING. Without it, the default frame ends at the current row, making LAST_VALUE equivalent to the current row's value!
Hard
NetflixSpotify
Percentile bucket each user into quartiles by spend ▼
Segment customers into 4 spend quartiles (Q1=lowest 25%, Q4=highest 25%) based on their total annual spend.
✅ Solution
WITH customer_spend AS ( SELECT customer_id, SUM(amount) AS total_spend FROM orders GROUP BY customer_id ) SELECT customer_id, total_spend, NTILE(4) OVER (ORDER BY total_spend ASC) AS quartile FROM customer_spend;
NTILE(n) divides the ordered result set into n approximately equal buckets. For deciles use NTILE(10), for percentiles use NTILE(100).
PATTERN 02
🔗 Joins & Self-Joins
INNER · LEFT · SELF · CROSS · ANTI-JOIN patterns
Joins combine rows from multiple tables. Self-joins compare rows within the same table. Anti-joins (using LEFT JOIN + IS NULL or NOT EXISTS) find records in one table with no match in another — extremely common in FAANG interviews.
Medium
MetaTwitter
Find customers who placed orders in 2023 but NOT in 2024 (Anti-Join) ▼
Find all customers who ordered in 2023 but did NOT place any order in 2024 — a classic churn analysis pattern.
✅ Solution
-- Method 1: LEFT JOIN Anti-Join (most common in interviews) SELECT DISTINCT o23.customer_id FROM orders o23 LEFT JOIN orders o24 ON o23.customer_id = o24.customer_id AND YEAR(o24.order_date) = 2024 WHERE YEAR(o23.order_date) = 2023 AND o24.customer_id IS NULL; -- Method 2: NOT EXISTS (often more readable) SELECT DISTINCT customer_id FROM orders o WHERE YEAR(order_date) = 2023 AND NOT EXISTS ( SELECT 1 FROM orders WHERE customer_id = o.customer_id AND YEAR(order_date) = 2024 );
Anti-Join pattern: LEFT JOIN + WHERE right_table.id IS NULL. Both methods return the same result but NOT EXISTS can be faster when the subquery uses indexes. Avoid NOT IN — it breaks with NULLs.
Medium
AmazonFlipkart
Self-Join: Find employees earning more than their manager ▼
The Employee table has a manager_id column referencing emp_id. Find all employees whose salary exceeds their direct manager's salary.
✅ Solution
SELECT e.emp_id, e.name AS employee_name, e.salary AS employee_salary, m.name AS manager_name, m.salary AS manager_salary FROM Employee e INNER JOIN Employee m ON e.manager_id = m.emp_id WHERE e.salary > m.salary;
Self-Join: Join a table to itself using aliases (e for employee, m for manager). This is the canonical interview question for self-joins. The key is e.manager_id = m.emp_id to link the relationship.
Hard
GoogleAirbnb
Mutual friends / mutual connections (Cross-Join pattern) ▼
Given a friends table with (user_id, friend_id), find all pairs of users who have at least 2 mutual friends.
✅ Solution
SELECT f1.user_id AS user_a, f2.user_id AS user_b, COUNT(*) AS mutual_friends FROM friends f1 INNER JOIN friends f2 ON f1.friend_id = f2.friend_id -- same friend AND f1.user_id < f2.user_id -- avoid duplicates (A,B) vs (B,A) AND f1.user_id <> f2.friend_id -- not the same person GROUP BY f1.user_id, f2.user_id HAVING COUNT(*) >= 2 ORDER BY mutual_friends DESC;
Key insight: Join friends to itself on friend_id = friend_id — that shared friend is the mutual connection. Use f1.user_id < f2.user_id to output each pair only once. HAVING filters the count.
PATTERN 03
🔄 CTEs & Subqueries
WITH clause · Nested subqueries · Correlated subqueries
CTEs (Common Table Expressions) make complex queries readable by naming intermediate result sets. Correlated subqueries reference the outer query and execute once per row — powerful but can be slow on large datasets. Know when to convert to JOINs.
Hard
MetaAmazon
User retention: % of users who returned the following month ▼
Given a logins table with user_id and login_date, calculate the monthly retention rate: percentage of users active in month M who were also active in month M+1.
✅ Solution
WITH monthly_users AS ( SELECT DISTINCT user_id, DATE_FORMAT(login_date, '%Y-%m-01') AS month FROM logins ), retention AS ( SELECT m1.month, COUNT(m1.user_id) AS current_users, COUNT(m2.user_id) AS retained_users FROM monthly_users m1 LEFT JOIN monthly_users m2 ON m1.user_id = m2.user_id AND m2.month = DATE_ADD(m1.month, INTERVAL 1 MONTH) GROUP BY m1.month ) SELECT month, current_users, retained_users, ROUND(100.0 * retained_users / current_users, 2) AS retention_pct FROM retention ORDER BY month;
Pattern: Chain multiple CTEs — each CTE builds on the previous. First deduplicate to monthly active users, then self-join on next month, then aggregate. Multi-step CTE chains keep code readable and debuggable.
Medium
MicrosoftSalesforce
Correlated subquery: products priced above category average ▼
Find all products whose price is above the average price of their respective category.
✅ Solution
-- Method 1: Correlated subquery SELECT product_id, product_name, category, price FROM products p WHERE price > ( SELECT AVG(price) FROM products WHERE category = p.category -- references outer query ); -- Method 2: CTE (better performance on large tables) WITH cat_avg AS ( SELECT category, AVG(price) AS avg_price FROM products GROUP BY category ) SELECT p.product_id, p.product_name, p.category, p.price FROM products p JOIN cat_avg c ON p.category = c.category WHERE p.price > c.avg_price;
Correlated vs CTE: Correlated subquery re-executes for each outer row (O(n) executions). The CTE-based approach computes averages once — always prefer it in production. Both produce identical results.
Hard
UberLyft
Rolling 7-day active users ▼
From a user_activity table (user_id, activity_date), compute the 7-day rolling count of distinct active users for each date.
✅ Solution
WITH daily_active AS ( SELECT DISTINCT activity_date, user_id FROM user_activity ) SELECT d1.activity_date, COUNT(DISTINCT d2.user_id) AS rolling_7d_users FROM daily_active d1 JOIN daily_active d2 ON d2.activity_date BETWEEN DATE_SUB(d1.activity_date, INTERVAL 6 DAY) AND d1.activity_date GROUP BY d1.activity_date ORDER BY d1.activity_date;
Rolling window via JOIN: Self-join on a date range (current day − 6 to current day) to pull in 7 days of data per anchor date, then COUNT DISTINCT. Alternative: use window function with RANGE BETWEEN INTERVAL 6 DAY PRECEDING AND CURRENT ROW in PostgreSQL.
PATTERN 04
📊 Aggregations & HAVING
GROUP BY · HAVING · ROLLUP · GROUPING SETS · Conditional Aggregation
Aggregations summarize data. The HAVING clause filters aggregated results (WHERE can't use aggregates). Conditional aggregation uses SUM(CASE WHEN...) to compute multiple metrics in one pass — a huge performance win.
Medium
GoogleMeta
Conditional aggregation: single-pass multi-metric report ▼
From an orders table, compute in a single query: total orders, total revenue, orders in 2023, orders in 2024, and % change — all per customer.
✅ Solution
SELECT customer_id, COUNT(*) AS total_orders, SUM(revenue) AS total_revenue, SUM(CASE WHEN YEAR(order_date) = 2023 THEN 1 ELSE 0 END) AS orders_2023, SUM(CASE WHEN YEAR(order_date) = 2024 THEN 1 ELSE 0 END) AS orders_2024, SUM(CASE WHEN YEAR(order_date) = 2023 THEN revenue ELSE 0 END) AS rev_2023, SUM(CASE WHEN YEAR(order_date) = 2024 THEN revenue ELSE 0 END) AS rev_2024 FROM orders GROUP BY customer_id HAVING COUNT(*) > 5 -- only customers with >5 orders ORDER BY total_revenue DESC;
Conditional aggregation (SUM(CASE WHEN...)) replaces multiple subqueries or self-joins. It computes multiple sliced metrics in a single table scan — far more efficient. This pattern appears in virtually every data analyst SQL interview.
Easy
AmazonWalmart
Find departments with more than 3 employees earning above average salary ▼
List departments where at least 3 employees each individually earn above the company-wide average salary.
✅ Solution
SELECT department, COUNT(*) AS high_earners FROM Employee WHERE salary > (SELECT AVG(salary) FROM Employee) GROUP BY department HAVING COUNT(*) >= 3 ORDER BY high_earners DESC;
WHERE vs HAVING: WHERE filters individual rows before aggregation. HAVING filters groups after aggregation. Rule: if you reference an aggregate function (COUNT, SUM, AVG), use HAVING; otherwise WHERE.
Hard
MicrosoftOracle
ROLLUP: Sales summary with subtotals and grand total ▼
Generate a sales report with totals at the product level, category level subtotals, and a grand total — all in one query.
✅ Solution
SELECT COALESCE(category, 'ALL CATEGORIES') AS category, COALESCE(product_name, 'SUBTOTAL') AS product_name, SUM(sales_amount) AS total_sales, COUNT(*) AS num_orders FROM sales GROUP BY ROLLUP(category, product_name) ORDER BY category, product_name;
ROLLUP automatically generates subtotals from right to left in the GROUP BY list, plus a grand total. NULLs in the result indicate the rollup rows — use COALESCE to label them. GROUPING SETS gives finer control over which combinations to include.
PATTERN 05
🏆 Top-N & Ranking
Top 3 per group · Nth highest · Leaderboards
Top-N queries are extremely common — finding the top 3 products per category, Nth highest salary, leaderboard positions. The key pattern is: window function to rank, then filter on rank in outer query.
Medium
AmazonGoogle
Top 3 products by revenue in each category ▼
Find the top 3 best-selling products (by total revenue) within each product category.
✅ Solution
WITH product_revenue AS ( SELECT p.product_id, p.product_name, p.category, SUM(o.revenue) AS total_revenue FROM products p JOIN order_items o ON p.product_id = o.product_id GROUP BY p.product_id, p.product_name, p.category ), ranked AS ( SELECT *, RANK() OVER (PARTITION BY category ORDER BY total_revenue DESC) AS rnk FROM product_revenue ) SELECT category, product_name, total_revenue, rnk FROM ranked WHERE rnk <= 3 ORDER BY category, rnk;
Top-N per group template: (1) Aggregate, (2) Apply window rank with PARTITION BY group, (3) Filter rank ≤ N. Choose RANK for "top N including ties", ROW_NUMBER for exactly N rows.
Easy
MetaLinkedIn
Nth highest salary (no window functions) ▼
Write a query to find the Nth highest distinct salary from the Employee table without using window functions.
✅ Solution
-- Set N = 3 for 3rd highest SELECT MAX(salary) AS nth_highest FROM Employee WHERE salary < ( SELECT MAX(salary) FROM Employee WHERE salary < ( SELECT MAX(salary) FROM Employee ) ); -- Generic approach for any N using subquery SELECT DISTINCT salary FROM Employee e1 WHERE (SELECT COUNT(DISTINCT salary) FROM Employee e2 WHERE e2.salary > e1.salary) = 2 -- N-1 salaries above it LIMIT 1;
Logic: The Nth highest salary has exactly N-1 distinct salaries above it. The correlated subquery counts salaries greater than the current row's salary; if that count equals N-1, it's the Nth highest. For interviews, modern DENSE_RANK approach is preferred.
Hard
DoorDashSwiggy
Top restaurant by orders in each city per month ▼
From an orders table with city, restaurant_id, and order_date, find the #1 restaurant per city per month by order count.
✅ Solution
WITH monthly_orders AS ( SELECT city, restaurant_id, DATE_FORMAT(order_date, '%Y-%m') AS month, COUNT(*) AS order_count FROM orders GROUP BY city, restaurant_id, month ), ranked AS ( SELECT *, ROW_NUMBER() OVER ( PARTITION BY city, month ORDER BY order_count DESC, restaurant_id ASC ) AS rn FROM monthly_orders ) SELECT city, month, restaurant_id, order_count FROM ranked WHERE rn = 1 ORDER BY city, month;
Tie-breaking: Use ROW_NUMBER when exactly 1 winner is needed. Add a deterministic tie-breaker (restaurant_id ASC) to ensure consistent results. PARTITION BY city, month creates a separate race per city-month combination.
PATTERN 06
🔀 Pivot & Unpivot
Rows to columns · Conditional aggregation pivot
Pivoting transforms row values into column headers. SQL doesn't have a native PIVOT in most dialects — use conditional aggregation (SUM/MAX + CASE WHEN) to simulate it.
Hard
MicrosoftInfosys
Pivot monthly sales: rows → columns per month ▼
Transform a sales table where each row is (product, month, amount) into a wide format with one column per month: product | Jan | Feb | Mar | ...
✅ Solution
SELECT product, SUM(CASE WHEN month = 'Jan' THEN amount ELSE 0 END) AS Jan, SUM(CASE WHEN month = 'Feb' THEN amount ELSE 0 END) AS Feb, SUM(CASE WHEN month = 'Mar' THEN amount ELSE 0 END) AS Mar, SUM(CASE WHEN month = 'Apr' THEN amount ELSE 0 END) AS Apr, SUM(amount) AS annual_total FROM sales GROUP BY product ORDER BY annual_total DESC;
Pivot pattern: SUM(CASE WHEN category = 'X' THEN value ELSE 0 END) for each distinct category value you want as a column. Use MAX instead of SUM for non-numeric pivots (e.g., status flags).
Medium
TCSWipro
Unpivot: wide format back to long format ▼
Given a wide table scores(student, math, science, english), unpivot to a long format: (student, subject, score).
✅ Solution
-- Using UNION ALL (works in all SQL dialects) SELECT student, 'Math' AS subject, math AS score FROM scores UNION ALL SELECT student, 'Science', science FROM scores UNION ALL SELECT student, 'English', english FROM scores ORDER BY student, subject;
UNION ALL unpivot: Each SELECT pulls one column and labels it. UNION ALL (not UNION) preserves duplicates and is faster since it skips the deduplication step. PostgreSQL also has UNNEST and the UNPIVOT operator.
PATTERN 07
📈 Running Totals & Cumulative Metrics
Cumulative SUM · Moving averages · Frame clauses
Running totals and moving averages use window function frame clauses. The default frame RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW computes cumulative sums. Bounded frames like ROWS BETWEEN 6 PRECEDING AND CURRENT ROW compute moving windows.
Medium
AmazonShopify
Cumulative sum of revenue by date ▼
Calculate the daily revenue and running cumulative total revenue for the year, ordered by date.
✅ Solution
SELECT order_date, SUM(revenue) AS daily_revenue, SUM(SUM(revenue)) OVER ( ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS cumulative_revenue FROM orders WHERE YEAR(order_date) = 2024 GROUP BY order_date ORDER BY order_date;
Double SUM pattern: The outer SUM() is the window function; the inner SUM(revenue) is the group aggregate. This computes daily totals first, then applies the cumulative window on top. Note ROWS vs RANGE: ROWS is usually preferred for performance.
Hard
NetflixHotstar
7-day moving average of daily active users ▼
Compute a 7-day moving average of daily active users to smooth out weekly seasonality.
✅ Solution
WITH daily_dau AS ( SELECT activity_date, COUNT(DISTINCT user_id) AS dau FROM user_activity GROUP BY activity_date ) SELECT activity_date, dau, ROUND( AVG(dau) OVER ( ORDER BY activity_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW ), 2 ) AS moving_avg_7d FROM daily_dau ORDER BY activity_date;
Frame clause ROWS BETWEEN 6 PRECEDING AND CURRENT ROW means: current row + 6 previous rows = 7-row window. For a trailing 30-day window, use ROWS BETWEEN 29 PRECEDING AND CURRENT ROW. ROWS uses physical row count; RANGE uses value distance.
PATTERN 08
🔍 String Patterns & Parsing
LIKE · REGEXP · SUBSTRING · POSITION · Email/URL parsing
String manipulation questions test ability to extract, clean, and validate text data — common in data engineering interviews. Master SUBSTRING_INDEX, REGEXP_LIKE, TRIM, REPLACE, and CONCAT.
Medium
GoogleMeta
Extract domain from email addresses ▼
From a users table with an email column, extract the domain part (e.g., gmail.com from alice@gmail.com) and count users per domain.
✅ Solution
SELECT SUBSTRING(email, POSITION('@' IN email) + 1) AS domain, -- MySQL shorthand: SUBSTRING_INDEX(email, '@', -1) AS domain_mysql, COUNT(*) AS user_count FROM users WHERE email REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' GROUP BY 1 ORDER BY user_count DESC;
SUBSTRING_INDEX(str, delim, count): count=-1 gets everything after the LAST occurrence of the delimiter. count=1 gets everything before the FIRST occurrence. Always validate email format first with REGEXP to exclude malformed entries.
Easy
TCSCognizant
Find users with duplicate email prefixes (before the @) ▼
Find all users who share the same email username (part before @) but have different domains — potentially duplicate accounts.
✅ Solution
WITH user_prefix AS ( SELECT user_id, email, SUBSTRING_INDEX(email, '@', 1) AS email_prefix FROM users ) SELECT u1.user_id, u1.email, u2.user_id AS dup_user_id, u2.email AS dup_email FROM user_prefix u1 JOIN user_prefix u2 ON u1.email_prefix = u2.email_prefix AND u1.user_id < u2.user_id ORDER BY u1.email_prefix;
PATTERN 09
📅 Date & Time Manipulation
DATEDIFF · DATE_TRUNC · DATE_ADD · EXTRACT · Cohort analysis
Date functions vary by SQL dialect — know MySQL vs PostgreSQL vs BigQuery differences. Key operations: date truncation, interval arithmetic, weekday extraction, and cohort date calculations.
Hard
AirbnbBooking.com
Cohort analysis: retention by sign-up month ▼
Given users (user_id, signup_date) and events (user_id, event_date), compute the monthly cohort retention table: for each signup cohort, what % of users were active in months 0, 1, 2, 3 after signup?
✅ Solution
WITH cohorts AS ( SELECT user_id, DATE_FORMAT(signup_date, '%Y-%m-01') AS cohort_month FROM users ), user_activity AS ( SELECT DISTINCT e.user_id, c.cohort_month, TIMESTAMPDIFF(MONTH, c.cohort_month, e.event_date) AS month_number FROM events e JOIN cohorts c ON e.user_id = c.user_id WHERE TIMESTAMPDIFF(MONTH, c.cohort_month, e.event_date) BETWEEN 0 AND 3 ), cohort_size AS ( SELECT cohort_month, COUNT(DISTINCT user_id) AS total_users FROM cohorts GROUP BY cohort_month ) SELECT ua.cohort_month, cs.total_users, ua.month_number, COUNT(DISTINCT ua.user_id) AS active_users, ROUND(100.0 * COUNT(DISTINCT ua.user_id) / cs.total_users, 1) AS retention_pct FROM user_activity ua JOIN cohort_size cs ON ua.cohort_month = cs.cohort_month GROUP BY ua.cohort_month, cs.total_users, ua.month_number ORDER BY ua.cohort_month, ua.month_number;
Cohort analysis is the #1 most-asked analytical SQL pattern at product-focused companies (Airbnb, Meta, Spotify). The key is computing the relative month since signup using TIMESTAMPDIFF or DATEDIFF, then grouping by cohort_month + month_number.
Medium
ZomatoUber Eats
Average delivery time by day of week ▼
From a deliveries table with order_time and delivery_time, find the average delivery duration in minutes broken down by day of week.
✅ Solution
SELECT DAYNAME(order_time) AS day_of_week, DAYOFWEEK(order_time) AS day_num, ROUND(AVG(TIMESTAMPDIFF(MINUTE, order_time, delivery_time)), 2) AS avg_delivery_mins, COUNT(*) AS total_orders FROM deliveries WHERE delivery_time > order_time -- data quality check GROUP BY DAYNAME(order_time), DAYOFWEEK(order_time) ORDER BY day_num;
Medium
GoogleBigQuery
Find users active for 3 or more consecutive days ▼
From a logins table, identify users who logged in on 3 or more consecutive days at any point.
✅ Solution
WITH daily_logins AS ( SELECT DISTINCT user_id, DATE(login_time) AS login_date FROM logins ), with_lag AS ( SELECT user_id, login_date, LAG(login_date, 1) OVER (PARTITION BY user_id ORDER BY login_date) AS prev1, LAG(login_date, 2) OVER (PARTITION BY user_id ORDER BY login_date) AS prev2 FROM daily_logins ) SELECT DISTINCT user_id FROM with_lag WHERE DATEDIFF(login_date, prev1) = 1 AND DATEDIFF(prev1, prev2) = 1;
Consecutive day check: Use LAG(date, 1) and LAG(date, 2) to look back. If the difference between the current date and the previous is 1 day, AND between previous and the one before is also 1 day → 3 consecutive days. Alternatively, use the Gaps & Islands pattern (Pattern 10).
PATTERN 10
🎯 Gaps & Islands
Consecutive sequences · Streak detection · Event grouping
The Gaps & Islands problem identifies consecutive groups (islands) within ordered data. Classic approach: subtract ROW_NUMBER from the value — if consecutive, the difference is constant, forming a group.
Hard
MetaGoogle
Find longest login streak per user ▼
From a logins table, find the longest consecutive login streak (days) for each user.
✅ Solution
WITH daily AS ( SELECT DISTINCT user_id, DATE(login_time) AS login_date FROM logins ), grp AS ( SELECT user_id, login_date, -- Subtract row_number from date → same value for consecutive dates DATE_SUB(login_date, INTERVAL ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date) DAY ) AS grp_key FROM daily ) SELECT user_id, MAX(COUNT(*)) OVER (PARTITION BY user_id) AS longest_streak FROM grp GROUP BY user_id, grp_key ORDER BY user_id;
Gaps & Islands key insight: For consecutive dates, date - row_number is constant. Rows with the same constant belong to the same consecutive group (island). GROUP BY that constant, COUNT the group size → that's the streak length.
Hard
AmazonWalmart
Find date ranges when a product was continuously in stock ▼
A stock_events table records daily product availability (1=in_stock, 0=out_of_stock). Find the start and end date of each continuous in-stock period per product.
✅ Solution
WITH in_stock AS ( SELECT product_id, event_date FROM stock_events WHERE in_stock = 1 ), grp AS ( SELECT product_id, event_date, DATE_SUB(event_date, INTERVAL ROW_NUMBER() OVER (PARTITION BY product_id ORDER BY event_date) DAY ) AS island FROM in_stock ) SELECT product_id, MIN(event_date) AS stock_start, MAX(event_date) AS stock_end, DATEDIFF(MAX(event_date), MIN(event_date)) + 1 AS days_in_stock FROM grp GROUP BY product_id, island ORDER BY product_id, stock_start;
PATTERN 11
⛔ NULL Handling
COALESCE · NULLIF · IS NULL · NULL in aggregates
NULLs are tricky — they don't equal anything, including themselves. NULL in arithmetic returns NULL. COUNT(*) counts NULLs; COUNT(col) ignores them. Master COALESCE, NULLIF, IS NULL / IS NOT NULL, and NULL-safe comparisons.
Medium
MicrosoftSAP
Fill NULL values with the most recent non-NULL value (forward fill) ▼
A stock_prices table has NULL prices on days when the market was closed. Fill each NULL with the most recent non-NULL price (forward fill).
✅ Solution
WITH numbered AS ( SELECT price_date, price, -- Create a group ID that increments only when price is not NULL COUNT(price) OVER (ORDER BY price_date) AS grp FROM stock_prices ) SELECT price_date, price, MAX(price) OVER (PARTITION BY grp ORDER BY price_date) AS filled_price FROM numbered;
Forward fill trick: COUNT(price) counts non-NULLs — it increments only on non-NULL rows, creating a stable group ID for each "island" of NULLs. Then MAX OVER that group propagates the last known value. PostgreSQL has a cleaner approach using LAST_VALUE IGNORE NULLS in some versions.
Easy
All Companies
NULL trap: Why NOT IN fails with NULLs ▼
Explain why this query returns 0 rows even though matching records exist: SELECT * FROM A WHERE id NOT IN (SELECT manager_id FROM Employee) when manager_id has NULLs.
✅ Fix & Explanation
-- ❌ BROKEN: Returns 0 rows if subquery contains any NULL SELECT * FROM A WHERE id NOT IN (SELECT manager_id FROM Employee); -- The issue: NULL comparison → x NOT IN (1, 2, NULL) -- → x != 1 AND x != 2 AND x != NULL -- → x != NULL is always UNKNOWN → whole expr = UNKNOWN -- ✅ FIX 1: Filter NULLs in subquery SELECT * FROM A WHERE id NOT IN ( SELECT manager_id FROM Employee WHERE manager_id IS NOT NULL ); -- ✅ FIX 2: Use NOT EXISTS (NULL-safe) SELECT * FROM A WHERE NOT EXISTS ( SELECT 1 FROM Employee WHERE manager_id = A.id );
NULL trap: This is a top interview gotcha. Any comparison with NULL returns UNKNOWN (not TRUE or FALSE). NOT IN short-circuits to UNKNOWN if the subquery contains any NULL. Always prefer NOT EXISTS over NOT IN when the subquery column may contain NULLs.
PATTERN 12
🔁 Recursive CTEs
Org hierarchy · BOM traversal · Number series generation
Recursive CTEs traverse hierarchical or graph data (org charts, bill of materials, category trees). Structure: anchor query UNION ALL recursive query that references the CTE itself. Supported in PostgreSQL, SQL Server, MySQL 8+, BigQuery.
Hard
AmazonMicrosoft
Find all direct and indirect reports for a manager ▼
Given an Employee table with manager_id, find ALL employees (direct and indirect) under a given manager (e.g., manager_id = 1).
✅ Solution
WITH RECURSIVE org_tree AS ( -- Anchor: start with the given manager SELECT emp_id, name, manager_id, 0 AS level FROM Employee WHERE emp_id = 1 UNION ALL -- Recursive: find direct reports of each found employee SELECT e.emp_id, e.name, e.manager_id, ot.level + 1 FROM Employee e INNER JOIN org_tree ot ON e.manager_id = ot.emp_id ) SELECT emp_id, name, level AS org_depth FROM org_tree WHERE emp_id <> 1 -- exclude the manager themselves ORDER BY level, name;
Recursive CTE structure:
1. Anchor: The base case (root nodes)
2. UNION ALL (not UNION — never deduplicate mid-recursion)
3. Recursive member: Joins the CTE to itself to find next level
Always include a termination condition (no more rows to join). Add a depth column to detect cycles and add a MAXRECURSION limit if needed.
Medium

Generate a date series / number sequence with recursive CTE ▼
Generate a continuous date series from 2024-01-01 to 2024-12-31 to use as a calendar dimension (fill gaps in time-series data).
✅ Solution
WITH RECURSIVE date_series AS ( SELECT CAST('2024-01-01' AS DATE) AS dt UNION ALL SELECT DATE_ADD(dt, INTERVAL 1 DAY) FROM date_series WHERE dt < '2024-12-31' -- termination condition ) SELECT dt AS calendar_date FROM date_series; -- Use this to find days with zero orders: SELECT ds.dt, COALESCE(COUNT(o.order_id), 0) AS order_count FROM date_series ds LEFT JOIN orders o ON DATE(o.order_date) = ds.dt GROUP BY ds.dt ORDER BY ds.dt;

📋 Deduplication
Remove duplicates · Keep latest record · Distinct on
Deduplication is essential in data pipelines. The standard technique: ROW_NUMBER() OVER (PARTITION BY key_columns ORDER BY sort_column) — keep rows where rn = 1.
Medium
All Data Eng Roles
Keep only the most recent record per user (dedup by latest) ▼
A user_profiles table has duplicate user records (multiple rows per user_id with different updated_at timestamps). Keep only the most recent row per user.
✅ Solution
-- Method 1: ROW_NUMBER (most versatile) WITH deduped AS ( SELECT *, ROW_NUMBER() OVER ( PARTITION BY user_id ORDER BY updated_at DESC ) AS rn FROM user_profiles ) SELECT * FROM deduped WHERE rn = 1; -- Method 2: Subquery with MAX (simpler but loses non-key columns) SELECT u.* FROM user_profiles u INNER JOIN ( SELECT user_id, MAX(updated_at) AS latest FROM user_profiles GROUP BY user_id ) latest_u ON u.user_id = latest_u.user_id AND u.updated_at = latest_u.latest;
ROW_NUMBER dedup is the universal template. Always specify what "latest" means (updated_at DESC, id DESC, etc.). Method 2 via MAX JOIN is simpler but can return multiple rows if two records share the exact same max timestamp.
Medium
AmazonFlipkart
Delete duplicate rows, keep one ▼
The orders table has exact duplicate rows. Write a query to delete all duplicates keeping exactly one copy of each.
✅ Solution
-- MySQL: DELETE using ROW_NUMBER in CTE WITH ranked AS ( SELECT order_id, ROW_NUMBER() OVER ( PARTITION BY customer_id, order_date, amount ORDER BY order_id ASC ) AS rn FROM orders ) DELETE FROM orders WHERE order_id IN ( SELECT order_id FROM ranked WHERE rn > 1 ); -- PostgreSQL: USING ctid (row identifier) DELETE FROM orders WHERE ctid NOT IN ( SELECT MIN(ctid) FROM orders GROUP BY customer_id, order_date, amount );

🌡️ Percentiles & Statistical Functions
PERCENTILE_CONT · MEDIAN · STDDEV · MODE
Statistical aggregates help in data analysis interviews. Know PERCENTILE_CONT (continuous interpolation), PERCENTILE_DISC (discrete value), STDDEV_POP, and how to compute medians without built-in functions.
Hard
GoogleData Science Roles
Compute median salary without PERCENTILE functions (MySQL) ▼
Find the median salary in each department in MySQL (which lacks PERCENTILE_CONT in older versions).
✅ Solution
-- PostgreSQL / modern SQL (cleaner) SELECT department, PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY salary) AS median_salary FROM Employee GROUP BY department; -- MySQL workaround using ROW_NUMBER WITH ranked AS ( SELECT department, salary, ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary) AS rn, COUNT(*) OVER (PARTITION BY department) AS cnt FROM Employee ) SELECT department, AVG(salary) AS median_salary FROM ranked WHERE rn IN (FLOOR((cnt + 1) / 2.0), CEIL((cnt + 1) / 2.0)) GROUP BY department;
Median logic: For odd n, the median is at position (n+1)/2. For even n, average of n/2 and n/2+1. The FLOOR/CEIL trick elegantly handles both cases — for odd n they equal the same position; for even n they give the two middle positions.
Medium
NetflixAnalytics Roles
P50, P90, P99 latency analysis ▼
From an api_calls table with response_time_ms, compute P50, P90, P95, and P99 latencies per API endpoint.
✅ Solution
SELECT endpoint, COUNT(*) AS total_calls, ROUND(AVG(response_time_ms), 2) AS avg_ms, PERCENTILE_CONT(0.50) WITHIN GROUP (ORDER BY response_time_ms) AS p50, PERCENTILE_CONT(0.90) WITHIN GROUP (ORDER BY response_time_ms) AS p90, PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY response_time_ms) AS p95, PERCENTILE_CONT(0.99) WITHIN GROUP (ORDER BY response_time_ms) AS p99 FROM api_calls GROUP BY endpoint ORDER BY p99 DESC;
PERCENTILE_CONT(0.99) means "the value at the 99th percentile" — 99% of calls are faster than this. BigQuery uses APPROX_QUANTILES for better performance on large datasets. SRE and infrastructure-focused data roles ask this frequently.
PATTERN 15
🔂 Sessionization
Session detection · Event grouping · Time-gap windows
Sessionization groups user events into sessions based on inactivity gaps. A new session starts when the gap between events exceeds a threshold (e.g., 30 minutes). Classic in product analytics at Uber, Airbnb, Google.
Hard
UberAirbnbGoogle
Assign session IDs to user events (30-min inactivity timeout) ▼
From a user_events table (user_id, event_time, event_type), assign a session_id to each event. A new session begins when there's a >30 minute gap since the last event for that user.
✅ Solution
WITH with_gap AS ( SELECT user_id, event_time, event_type, -- Flag: 1 if this event starts a new session CASE WHEN TIMESTAMPDIFF(MINUTE, LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time), event_time ) > 30 OR LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time) IS NULL THEN 1 ELSE 0 END AS new_session_flag FROM user_events ) SELECT user_id, event_time, event_type, new_session_flag, -- Cumulative sum of flags = session ID per user SUM(new_session_flag) OVER ( PARTITION BY user_id ORDER BY event_time ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW ) AS session_id FROM with_gap ORDER BY user_id, event_time;
Sessionization in 2 steps:
1. Use LAG to compute the time gap to the previous event; flag 1 if gap > 30 min or first event
2. Cumulative SUM of flags = session ID (increments at each session boundary)

This is the gold-standard pattern used in production analytics pipelines at Uber, Lyft, and Airbnb.
Hard
UberOla
Session metrics: average session duration and events per session ▼
Using the sessionized data from above, compute session-level metrics: session duration, number of events, and first/last event type per session.
✅ Solution
WITH sessionized AS ( -- (same CTE from previous question) ... ) SELECT user_id, session_id, MIN(event_time) AS session_start, MAX(event_time) AS session_end, TIMESTAMPDIFF(MINUTE, MIN(event_time), MAX(event_time) ) AS duration_minutes, COUNT(*) AS event_count, MIN(event_type) AS first_event, MAX(event_type) AS last_event FROM sessionized GROUP BY user_id, session_id ORDER BY user_id, session_start;
Session aggregation: Once session IDs are assigned, simple GROUP BY user_id + session_id lets you compute any session-level metric. MIN/MAX on event_time gives start/end; COUNT gives events; TIMESTAMPDIFF gives duration.

For "first event type" and "last event type" use FIRST_VALUE / LAST_VALUE window functions for more control.
